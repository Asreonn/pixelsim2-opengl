# AGENTS

Guidance for agentic coding in the PixelSim2 repository.

## Project Snapshot
- Language: C11; configured via `CMakeLists.txt`.
- Build system: CMake with a generated `build/` directory.
- Output binary: `PixelSim2`.
- Core dirs: `src/`, `include/`, `assets/`, `external/`, `docs/`.
- Generated artifacts live in `build/` (avoid manual edits).

## Build / Run / Test / Lint
- Configure (release default): `cmake -S . -B build`
- Configure (debug): `cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug`
- Build: `cmake --build build`
- Run: `./build/PixelSim2`
- Clean: delete `build/` and reconfigure.
- Dependencies: OpenGL + glfw3 + pthreads; GLAD is vendored in `external/`.
- Compile commands: `build/compile_commands.json` (generated by CMake).
- Release flags include `-march=native -ffast-math` for CPU optimization.

## Repo Layout
- `src/`: implementation files, grouped by module (core, world, physics, materials, render, input).

## Code Style and Conventions

### Formatting
- Indentation: 4 spaces; no tabs.
- Braces: opening brace on the same line (`if (...) {`).
- Use blank lines to separate logical blocks.
- Keep lines reasonably short; wrap long argument lists.
- Prefer single-statement early returns (`if (!ptr) return NULL;`).
- Use `//` comments for short notes; avoid comment noise.

### Includes
- Order includes: standard library headers, third-party headers, then project headers.
- Separate include groups with a blank line.
- Use angle brackets for system headers and quotes for repo headers.
- In headers, forward-declare structs where possible to reduce includes.
- In source files, include the matching header when applicable.

### Types and Constants
- Use fixed-width typedefs from `include/core/types.h` (`u8`, `i32`, `f32`, `f64`).
- Use `bool` from `<stdbool.h>`; return `bool` for success/failure.
- Use enums from `core/types.h` for material states and interaction types.
- Use constants from `include/core/config.h` for world sizes and tuning.
- Use `Color` and helper macros (`COLOR_RGB`, `COLOR_RGBA`) for colors.
- OpenGL handles use `u32` in renderer/shader APIs.

### Naming
- Functions/variables: lower_snake_case (e.g., `world_update`).
- Types/structs: PascalCase (e.g., `Renderer`, `MaterialDef`).
- Enum values/macros: UPPER_SNAKE_CASE with module prefix when relevant.
- File names: lower_snake_case and module-scoped directories.
- Public functions are usually prefixed by module (`renderer_`, `world_`, `materials_`).
- `static` for file-local helpers and private state.

### Control Flow
- Prefer early returns on error paths.
- Keep hot loops tight and avoid unnecessary allocations.
- Use `const` for read-only inputs and lookup tables.
- Use deterministic math utils (`rand_*`) when randomness is needed.

### Error Handling and Logging
- Return `false`/`0` on failure from init or load routines.
- Call sites check return values and abort gracefully when needed.
- Report errors via `fprintf(stderr, ...)`.
- Use `printf` for user-facing status messages.

### Memory and Ownership
- Allocate with `malloc`/`free`; always check for `NULL`.
- Free temporary buffers on all exit paths.
- Favor stack allocation for small fixed-size buffers.
- Avoid reallocating per-frame in tight loops.

### Headers and API Shape
- Use include guards with `PIXELSIM_<MODULE>_H`.
- Keep headers focused on types and function declarations.
- Minimize transitive includes; forward-declare where possible.
- Document non-obvious structs or magic values with brief comments.

### Modules and Responsibilities
- `core/`: math, config, shared types, thread pool.
- `world/`: grid, chunks, pixel storage, active pixel tracking.
- `physics/`: movement, gravity, temperature, pressure, phase transitions.
- `materials/`: material IDs/defs, registry, interactions, material cache.
- `render/`: OpenGL setup, shader handling, PBO texture updates.
- `input/`: input polling and brush application.

### Performance Systems
- **Thread Pool** (`core/thread_pool.h`): Multi-threaded chunk processing with checkerboard pattern.
- **Material Cache** (`materials/material_cache.h`): Pre-computed lookup tables with inline macros (`MAT_CACHE_*`).
- **Active Pixel List** (`world/chunk.h`): O(active) instead of O(n²) iteration per chunk.
- **Adaptive Chunk Sleep**: Chunks with no changes sleep automatically.
- **PBO Double Buffering** (`render/renderer.h`): Async texture upload to GPU.

### Adding or Updating Materials
- Define IDs in `include/materials/material_ids.h`.
- Add material definition in `src/materials/definitions/`.
- Register new materials in `src/materials/material_registry.c`.
- Add interactions in `src/materials/interactions.c`.
- Ensure colors use `Color` helpers for consistent RGBA packing.
- Material cache is rebuilt on init; new materials are automatically cached.

### Adding New Source Files
- Add new `.c` files to the `SOURCES` list in `CMakeLists.txt`.
- Add matching headers under `include/<module>/` when the API is shared.
- Keep module boundaries clean; avoid cross-module globals.

### Rendering and Assets
- Shaders are loaded from `assets/`; keep paths consistent with renderer.
- OpenGL errors are handled via return codes and stderr logs.
- `renderer_update_texture` is the main bridge from world data to GPU.

### Simulation Notes
- The simulation uses a fixed timestep (`FIXED_TIMESTEP`).
- Chunk activation is used for performance; avoid waking every chunk.
- Temperature, pressure, and phase transitions live in `physics/`.

### Documentation
- Use `docs/project_overview.md` for domain concepts and material tables.
- Keep new design notes in `docs/` rather than inline in source.

## Agent Tips
- Respect existing structure; avoid reformatting unrelated code.
- Do not edit generated files under `build/`.
- When touching a module, read the header in `include/` first.
- Keep public API changes minimal and update call sites consistently.
- Update `CMakeLists.txt` when adding/removing source files.
